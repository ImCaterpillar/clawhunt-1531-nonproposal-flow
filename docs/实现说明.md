# 实现说明 — #1531 非提案业务试点

## 需求还原

企业知识库与多 Agent 协作系统（系列 50 单）的拆单之一。本单范围：
**选择一个公司级非提案任务串联知识、编排、审批与评测**。

验收标准：**交付完整输入、证据、结果及验收记录**。

## 选型

选择**差旅申请与审批流**作为代表性公司级非提案任务——它具备
公司常态业务的全部要素：输入、政策知识校验、流程编排、审批门、
事后评测、归档。数据全部脱敏。

## 设计

### 1. 流程配置 schema

`schema/flow_config.schema.json`（draft-07）：
- `flow_id` / `task_type` / `steps`（2+ 步骤，kind 枚举：collect_input /
  knowledge_check / orchestrate / approval / evaluate / archive）
- `knowledge_mounts`（挂载差旅政策/预算/审批矩阵知识）
- `approval_gates`（是否需审批、审批人角色、政策）
- `evaluation`（评测 criteria + target）

### 2. 执行器四要素（对应验收）

`BusinessFlowRunner.execute()` 返回：
- `input`：完整输入快照（脱敏）
- `evidence[]`：每步一个 evidence（步骤/类型/快照/时间戳）
- `result`：最终状态（status/workflow_id/approval/archived）
- `acceptance`：验收记录（complete_input / evidence_count /
  policy_compliant / archived）

### 3. 审批门（业务规则）

- 金额 ≤ 3000（脱敏红线）→ 自动通过；
- 金额 > 3000 → `pending_manager`（转 line_manager 人工审批）。
集成测试 6/7 验证小额自动、大额转人工。

### 4. 知识串联

知识校验步骤读取 `knowledge_mounts` 并检查预算红线（脱敏：10 万元
预估上限）——体现"串联知识"而非只有流程。

### 5. 评测与归档

事后评测按 criteria 检查状态与审批完成度；归档步骤固化为已归档；
验收记录汇总四要素（测试 9 逐一断言）。

## 修复记录

- `_do_approval` 初版对大额金额 `approved` 恒 True（误用 gate.required
  作为审批结果）→ 修复为小额 approved=True、大额 approved=False 并
  转 pending_manager；
- `_acceptance` 初版引用未定义 `_last_ev` → 改为直接接收 evidence 计算。

## 与系列其他单的关系

与 02 角色卡（审批人角色）、21 方法论、30 评测对照等呼应：本单把
知识/编排/审批/评测**串联在一个真实业务流**里，而非独立模块。
